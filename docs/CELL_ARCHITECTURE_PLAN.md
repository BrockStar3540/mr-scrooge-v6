# V5 Cellular Architecture — Migration Plan
**Drafted 2026-07-04 · Status: PROPOSAL for Brock review · Owner: Claude sessions**

## 0. The change in one paragraph

Invert the hierarchy. Today: two global signal modules (direction_v2, momentum_v3) compute
scores for every pair, and 48 cells exist only as configuration sprinkled across five files
(profiles, tuning, playmaker gates, calibration, locks). Target: **the CELL is the
first-class unit.** Each PairModule carries a session gate and, inside it, one CellModule
per (session × tradeable setup), each owning its complete configuration: entry fingerprints,
side policy, exit geometry, sizing, tripwires, lineage. Direction_v2 and momentum_v3 are
retired as strategy engines and archived; what survives of them is (a) the shared indicator
feed and (b) any cell-local validated formula that happened to be discovered through them.

Evidence basis: direction-as-strategy falsified at every horizon (2026-07-04); movement
timing validated at 20-30m (48/48, AUC 0.62-0.69); per-cell envelope structure and exits
dominate outcomes; every validated edge is cell-local. The architecture should say what the
data says.

## 1. What each layer becomes

```
OANDA feed → MarketView (UNCHANGED — shared indicator computation, plus feed extension)
              │
    PairModule (per pair) — session gate (which sessions this pair trades, per config)
              │
    CellModule (per pair × session) — THE strategy unit. Owns:
      entry:   timing fingerprint(s) (20/30m atr_5m band + cell-specific ranges,
               percentile form), envelope screens (dead/pierce separators),
               optional formula setups (e.g. GBP london rvol band @240m)
      side:    side policy (see §3 — the key design decision)
      exit:    per-cell geometry (SL/trigger/trail/horizon) — replaces global exit_config
      size:    risk-normalized units (risk% / (stop × pip value)), regime size-modulators
      guard:   tripwires (monthly covariate health + fast live-EV trip), n-floor status
      meta:    lineage per parameter, drift labels, last-refit stamp
              │
    Portfolio layer (playmaker successor) — UNCHANGED duties, cell-agnostic:
      max concurrent, per-currency-direction cap, spread sanity, pick among qualifying cells
              │
    RatchetManager — UNCHANGED mechanics, parameterized per trade from the cell's exit block
```

One config artifact replaces five: `config/cells/<PAIR>_<session>.json` (or one
`cell_config.json`) — generated by the monthly refit pipeline, hand-editable, hot-reloadable,
every value carrying `lineage:` and `drift:` fields.

## 2. What gets archived vs retained

ARCHIVE (move to modules/archive/, keep importable for rollback + replay):
- direction_v2.py, momentum_v3.py, direction_profiles.py, momentum_profiles.py,
  factor_sweep.json (as calibration input it survives only if a retained formula needs an
  anchor — otherwise archived), profile_shadow.py (its A/B question dies with the modules)
- Inversion machinery (inverted_live_cells, inverted_live_directions): the concept dissolves
  — a cell's side policy states its side directly; no "native signal" to flip
- disabled_cells as a mechanism: replaced by cells simply having no qualifying setups
  (a cell with empty entry config trades nothing); structural Tier-3 cells ship with
  empty/blocked config, with the evidence in their meta block

RETAIN UNCHANGED:
- Feed/MarketView (+ planned extension: q_yzv_m5, q_dc_*, q_bbwp_m5, q_vwap_dist, q_obv/adl)
- RatchetManager mechanics (gains per-trade parameterization)
- Portfolio caps, exposure map, lock-guard AUDIT machinery (repurposed: snapshot/attribution
  for cells, "priority-analysis" flags — enforcement semantics already slated for removal)
- All instrumentation (CAL, FORMULA stamps adapt to read cell configs; scorers unchanged)
- Truth matrix + monthly refit pipeline (becomes the cell-config generator)

MIGRATION-SENSITIVE (needs explicit mapping, §4 risk 1):
- Live-validated gates expressed in module outputs (d_cert/m_cert floors on GBP_USD/ny,
  USD_JPY/asia, AUD_JPY/asia, AUD_USD/london): these values are meaningless without
  direction_v2/momentum_v3. Each must be re-expressed in raw-indicator terms from that
  cell's live-trade stamps, or retired with its cell's setup redefined. No d_cert floor
  survives the migration as-is.

## 3. The one open design decision: side policy per cell

Every trade needs a side; direction prediction is falsified as a general capability.
Per-cell side policy options (each cell gets exactly one, from evidence):
  a. FORMULA side — the setup itself defines the side (GBP_USD/london/long rvol band = long;
     AUD_JPY/ny/short regime edge = short). Cleanest; applies to validated formulas.
  b. LEAN side — cells with a PERSISTENT lean (28/48) trade only the lean's side when the
     lean's feature confirms (e.g. USD_JPY/london: atr_h1_rel high → per its sign).
  c. NO-SIDE — cells with no lean and no formula (20/48) DO NOT TRADE until a setup is
     discovered for them. This is the honest consequence of the direction falsification:
     a cell without a sided setup has no trade, not a coin-flip trade.
RECOMMENDATION: implement exactly these three; no composite-score side-picking anywhere.
BROCK DECISION NEEDED: confirm (c) — accepting that ~1/3 of cells go quiet until the
monthly discovery loop finds them a sided setup. (The alternative — trade them on thin
tiebreakers — is how the old book bled.)

## 4. Risks and their mitigations

1. **d_cert/m_cert gate loss** (§2): re-derive each affected cell's gate from raw stamps
   before cutover; any cell whose edge can't be re-expressed goes NO-SIDE until refit.
2. **Statistical continuity**: cell identity (pair×session×side) is preserved, so live
   per-cell records remain comparable. Tag the cutover timestamp in every log line
   (engine=cell_v1) so eras never mix (the cross-era lesson, institutionalized).
3. **Regression risk**: full shadow before cutover (§5 phase C) — the new stack runs
   dual-stamp for ≥1 week; cutover requires the shadow to show no unexplained divergence
   in what it WOULD have traded vs. expectations. Rollback = single git tag + restart
   (old modules stay importable).
4. **Complexity creep**: the CellModule interface is frozen at the §1 field list. New
   capabilities enter via config fields with lineage, never via new module types.
5. **The engine keeps trading throughout**: all phases before cutover are additive
   (new code paths shadow-only). No trading gap.

## 5. Phases

- **A. Spec + schema (1 session).** CellModule interface, cell-config JSON schema with
  lineage/drift fields, side-policy enum, per-cell exit schema. Deliverable:
  docs/CELL_ARCHITECTURE_SPEC.md + example configs for 3 cells (GBP london formula cell,
  a lean cell, a NO-SIDE cell). Includes the d_cert-gate re-derivation for the 4 affected cells.
- **B. Config generation (1 session + Mini compute).** Extend the monthly refit pipeline to
  emit the full cell-config artifact (it already produces calibration + formulas + tripwires;
  this consolidates into the new schema). Generate v1 configs for all 48 cells from current
  clean evidence: Layer-1 formula cell, Tier-1/2 timing+envelope cells, Tier-3 blocked,
  NO-SIDE where §3c applies.
- **C. Engine implementation + shadow (1-2 sessions).** PairModule/CellModule classes,
  portfolio layer adaptation, per-trade exit parameterization; run as CELL_SHADOW dual-stamp
  alongside the live stack ≥1 week (market-open week, not weekend). Scorer compares.
- **D. Cutover (1 session, Brock go).** Flip execution to the cell stack, archive old
  modules, retire inversion/disable mechanisms, single annotated commit, rollback tag.
- **E. Cleanup + docs (1 session).** README/spec/CHANGELOG/vault updates, memory updates,
  locked-cells → priority-flag conversion completes, dashboard CELLS tab reads new configs.

Realistic calendar: A+B this weekend (market closed = ideal), C shadow running next week,
D the following weekend if the shadow is clean. The GBP formula's per-cell exit (Layer-1
wiring gap) ships early inside C — it's the same mechanism, first consumer.

## 6. What does NOT change

Strategy-free doctrine (this IS its full expression: no strategies, no global signal
opinions — cells with measured setups). Broker-truth methodology. The gauntlet (clean
corpus, sequential, deep-OOS classifier, plateaus, drift labels, live veto). Monthly refit
cadence. Portfolio risk caps. The instruments-first culture: nothing gates until it stamps.
